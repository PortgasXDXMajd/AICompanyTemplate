# specs/

A spec says what will be built or done, and how we will know it worked, before anyone starts. Anything that touches a product repo or will be seen outside the company gets one, and so does anything the CEO wants thought through first. Specs cover product features and non-code work alike (a landing page, an outreach campaign, a pricing test).

- File name: `NNN-short-name.md`, numbered in order (`001-waitlist-page.md`).
- Copy `_template.md`. One page is the target. If it needs more, the scope is too big: split it.
- Status flow: `draft` → `approved` (by the CEO) → `building` → `shipped` or `dropped`.
- Work does not start on a `draft`. When a spec ships, link its demo and move the roadmap item to Done.
